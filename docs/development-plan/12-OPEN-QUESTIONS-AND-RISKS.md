## Confirmed payment decision (23 October 2026)

**Razorpay is the selected gateway for the entire platform's applicable paid registration fees, book purchases, prepaid coaching subscriptions/passes and renewals.** Use Razorpay Standard Checkout with backend-created orders; never trust frontend prices, success status or purchased entitlements. PaymentService/RazorpayPaymentProvider isolates SDK calls. Reuse the existing payment API IDs and Order/PaymentAttempt/Job model set. Backend verifies signature, provider capture, ownership, bound order/payment, amount/currency and environment; independently signed webhooks and reconciliation share an idempotent settlement path with exactly-once database activation, then frontend retrieves authoritative order status.

Gateway selection is no longer an open question and does not need reconfirmation. Development/provider integration testing use Test Mode only; live payments during implementation/testing require explicit approval. **The exposed test secret is compromised: owner-confirmed revocation/rotation is mandatory before payment integration**, not just before deployment. No existing secret is copied and no credential rotation/provider action was performed in this documentation-only update. Recurring Razorpay subscriptions/mandates remain out of scope unless separately approved.

Still unresolved: applicability and amounts of fees/prices, paid-registration review/activation rights (Q01); free join, pass duration, prepaid renewal extension and price consistency (Q02); tax treatment, refund eligibility/process, receipt versus tax invoice, issuer details and invoice compliance (Q09). INR is the existing proposal, not a finalized multi-currency business policy. Capture configuration and operational reconciliation ownership must be confirmed before provider setup; only verified captured payments can fulfill, regardless of configuration. Admin financial summaries may report verified captured amounts grouped by currency/mode, not unapproved accounting/tax definitions.
