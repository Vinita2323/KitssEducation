## Contract refinements and limits

- B16 permits verified active/suspended identities to suspend/restore with reason and `expectedRevision`; pending/archived activation, self edits and every super-admin edit are rejected. Version changes invalidate existing sessions. This is not an account-verification override.
- B18 updates only an existing ordinary staff account's code-allowlisted permissions with `roles:["admin"]`; only super admins have `accounts.roles.manage`. Students cannot be promoted and super admins cannot be created/demoted here. Initial staff still uses the existing invitation/OTP workflow; operator super-admin lifecycle remains protected.
- B19 extends the existing enrollment endpoint with `kind=book` read-only support. Record state and captured source verification are distinct; a displayed record is not an access grant. B20 and unsupported book B21 stay gated.
- B38 exposes safe event identity/action/time/resource/reason only; B39 omits tokens, job payload/result summaries, hashes and candidate data. Jobs are read-only; payment reconciliation remains B24.
- B01 retains the existing verified financial shape and adds `operations:{asOf,totals}` with explicitly labelled total records, including drafts/inactive rows. These counts are not attendance, revenue or approvals.
- Remaining gate IDs are Q01/Q02/Q04/Q05/Q06/Q07/Q09/Q11, real SMTP/scanner/licensing and Razorpay rotation/authorized Test Mode acceptance. Stage 10 does not invent the corresponding policies or claim full original-scope production acceptance.

## Final gap closure contract refinement

Video reuses POST `/media`, GET `/media/:id/content`, existing lesson CRUD and A50-A52; no new endpoint, model collection, auth scheme or payment integration. A51 adds `video:{assetId,url,mime,durationSeconds}`. A52 validates `positionSeconds` against inspected duration and requires the current `videoAssetId` when writing a video position; unknown/client duration/user/course fields are rejected. Existing `expectedRevision`/idempotent semantic replay remain. Position/activity/completion persist in LearningProgress; course percentages remain server-derived from current published lesson progress. Changed video associations reset displayed old resume/completion without granting/removing enrollment. Completion is a learner activity marker, not an attendance/certification claim. Ended events queue behind in-flight saves; lesson teardown cancels progress work and identity epochs prevent old read/CSRF/write continuations under a changed account. Final focused browser evidence covers all three boundaries; unchanged seven-width results are reported separately.

That final video-stage snapshot closed F20 plus necessary upload-progress, range-header and lesson-status accessibility integration. The subsequent final audit now also implements the F15 selectable/accessibility PDF text layer; optional profile avatar and reserved publicFeatures semantics still require purpose/policy/scope decisions. No policy-dependent workflow is enabled.
