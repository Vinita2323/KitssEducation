Fast-start MP4 is required: one H.264 Baseline/Constrained Baseline/Main/High yuv420p stream, up to 1920x1080/60fps/level 4.2, optional mono/stereo AAC-LC, positive duration up to two hours. Unsupported tracks/codecs, malformed/truncated boxes and failed decoding are rejected. Default video limit is 256 MiB, bounded by global storage limit. Application upload code uses native File/FormData and disk-backed Node streams without accumulating complete videos in JavaScript buffers. Native tools use a 64 MiB single-allocation cap (not a total-memory OS sandbox), bounded output and timeouts. Disk checks preserve a configurable 1 GiB reserve beyond each incoming maximum; they are preflight checks, not distributed capacity reservations. ## Delivery, progress and safety

POST `/api/v1/media` retains purpose/idempotencyKey/file, using `lesson_video`; lesson CRUD retains videoAssetId. Existing GET `/media/:id/content` provides MP4 MIME, length, Accept-Ranges, valid bounded/open/suffix 206 Content-Range and invalid-range 416 with `bytes */size`. Each new request rechecks current account/session, lesson/course publication, source rights, exact current lesson association, enrollment/source capture/expiry/revocation and stored-byte integrity. Explicit published public previews use the existing distinct permission; enrolled progress still requires enrollment. Admin preview requires media.read and ready/clean status. Detached originals cease to be student-readable unless another currently authorized lesson still legitimately references them. Previously delivered bytes cannot be revoked; this is not DRM.

A51 returns `video:{assetId,url,mime,durationSeconds}` and owner progress. A52 accepts status/expectedRevision and video position/current asset ID, rejects client duration/course/user assignment, derives duration from inspected MediaAsset, and validates range/source/revision. Owner/course/lesson/video bindings prevent cross-account/stale-video writes. Course percentage is derived from current published lesson activity; explicit lesson completion remains the existing learner activity marker, not attendance proof or certification. Position saves every 15 seconds during playback plus pause/hidden/manual save, normally at least five seconds apart. An ended event queues completion behind an in-flight position save. Lesson teardown aborts pending work; the existing identity epoch now guards the complete read/CSRF/write continuation to prevent an old playback save from being sent under a changed account. Visible conflicts/network errors do not imply a save succeeded. Resume uses the last successful server save; abrupt termination may lose the final unsaved interval.

No sensitive-intake policy, paid status override, enrollment grant, official-result trust bypass, scanner bypass, untrusted external stream URL or permanent public video link was introduced. Existing text/PDF handling and route styling remain. Same-origin `/api` routing/proxy is retained for native media. Source licensing confirmation remains required at course publication.

## Setup and exact operational gates

Start frontend/backend from repository root in separate terminals using `npm.cmd run client` and `npm.cmd run server:dev`. Existing local Vite proxy is unchanged. The [README](README.md#final-gap-closure-private-video-lessons) documents supported format, existing API extensions, configuration defaults and isolated commands. New optional environment keys: MEDIA_FFPROBE_PATH, MEDIA_FFMPEG_PATH, MEDIA_VIDEO_MAX_BYTES, MEDIA_VIDEO_UPLOAD_TIMEOUT_MS, MEDIA_VIDEO_INSPECTION_TIMEOUT_MS, STORAGE_MIN_FREE_BYTES. No new secret is required.

Read-only configuration/loopback check found scanner disabled and its configured local port unreachable; custom executable paths are also absent from the application configuration and the tools are not on PATH. An owner/operator must configure the installed executable paths and provision/maintain/independently accept ClamAV with current signatures and video-compatible stream-size/time limits before real publication. Missing inspection tools reject uploads safely; missing scanning keeps validated uploads quarantined/unlinkable. Supply real authorized video/instructor/course licensing/source evidence and validate storage reserve, backup/restore, throughput and future proxy timeout/capacity settings. No real course-content publication acceptance is claimed.
